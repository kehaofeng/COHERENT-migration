# 五个规划环境的简化三维场景设计 v1

本版依据 `env/env0.json`—`env/env4.json` 的 102 条任务的节点、`ON`、`INSIDE`、`LEADING TO` 和目标编制。它是**布局与装载方案**，还不是已运行的 OmniGibson 场景。已有的 Merom、grocery_store_cafe 等数据集场景仅可作资产来源，不预设它们与某个 `env` 相同。

## 共用实施规则

1. 每个 `env` 只建一个可重复使用的基础布局：地面、房间/区域、通道、固定家具/设施及机器人的初始工作位。每条任务从同一基础布局重置，按该任务的 `init_graph` 增加小物体、容器和任务专用设施；**不能把多条任务的终态累加**。
2. 第一阶段用简单几何体搭地面、墙、台面和柜体，先检查空间关系及导航路径；第二阶段按 `model_mapping.csv` 选定具体模型后逐件替换。几何体只是位置占位，不算模型选型完成。
3. 全部坐标为初稿，单位米，采用 `x` 向右、`y` 向上、`z` 向上；表中的 `(x,y)` 是物体在地面的中心。台面物品的 `z` 必须在实际模型加载后由台面碰撞包围盒计算，不能把表中地面坐标直接作为物品的三维姿态。
4. 房间名、地板名及 `Region` 是逻辑区域和碰撞地面，不按普通 DatasetObject 选择模型。门宽、通道宽初稿取 ≥1.2 m；门洞应真实连通。双机械臂、机器狗、无人机和篮子都按图中的独立实体处理，不能拿家具模型替代。
5. `ON`/`INSIDE` 从每条任务的初态生成目标放置位置；同一容器要预留多个物体的容量。无人机着陆台面须留无障碍区域，台面是否足够大、能否承重和避碰要在实际模型与机器人尺寸确定后验证。
6. 加载顺序：空地面 → 一个台面 → 一个小物体 → 一台机器人 → 单任务所需设施 → 全基础布局。上一步失败就记录内存、模型路径或碰撞错误，不继续叠加。此前本机 15 GiB 内存在 Isaac Sim 启动阶段已发生 OOM；简化布局可能减轻负担，但不能保证本机能运行。

## 需要验证后才能成为运行场景

- 按 [`model_mapping.csv`](reports/all_env_models/model_mapping.csv) 与 [`model_selections.json`](config/model_selections.json) 确认每个实例的 `category/model`；本文件中的布局**没有增加任何已确认模型**。
- 为每个固定物体换成真实资产后，用包围盒和碰撞检测校正上述中心坐标，并重新计算台面物品的高度、无人机着陆净空、门洞与导航路径。
- 对冰箱、微波炉、柜子、盒子、购物篮、垃圾桶、水槽和收银机验证所需开合、容纳及交互状态。原规划的 `ON`、`INSIDE` 是语义要求，不能仅凭物体外观看起来相邻就视为满足。
- 本机先试最小场景；若 Isaac Sim 基础启动仍内存不足，把同一套简化配置搬到内存更充足的服务器再做实际加载与浏览器预览。
